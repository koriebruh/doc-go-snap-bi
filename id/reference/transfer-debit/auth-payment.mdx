## Auth Payment

Alur otorisasi/capture/void/refund bergaya kartu: tahan dana dengan AuthPayment, lalu capture, void, atau refund; setiap operasi tulis punya panggilan query pasangannya.

<CodeGroup>
```go example.go
resp, err := transferdebit.AuthPayment(ctx, transport, hb, transferdebit.AuthPaymentRequest{
	PartnerReferenceNo: "2020102900000000000001",
	MerchantID: "...",
	Title: "...",
})
if err != nil {
	// errors.Is(err, snap.ErrBadRequest), snap.ErrUnauthorized, etc.
}
```
</CodeGroup>

### `AuthPayment`

AuthPayment memanggil endpoint SNAP Auth Payment (Service Code 63, HTTP POST — tanpa override method; tab Overview pada riset menandainya GET, tetapi setiap contoh kerja di ketujuh endpoint Auth Payment berbentuk POST dengan body JSON wajib, dan jalur signing package ini tidak punya representasi untuk GET yang membawa body). hb harus sudah membawa setiap field yang dibutuhkan snap.HeaderBuilder kecuali Body, yang diisi sendiri oleh AuthPayment agar byte hasil marshal yang persis sama dipakai baik untuk signing maupun body di jalur kirim.

Operasi ini tidak idempotent dan package ini tidak melakukan retry. Caller yang me-retry panggilan yang gagal atau timeout sebaiknya memakai ulang X-EXTERNAL-ID yang sama, karena deteksi duplikat di sisi server berpatokan pada header tersebut.

```go
func AuthPayment(ctx context.Context, t *snap.Transport, hb snap.HeaderBuilder, req AuthPaymentRequest) (AuthPaymentResponse, error)
```

**Request &mdash; `AuthPaymentRequest`**

AuthPaymentRequest adalah body request untuk API Auth Payment (Service Code 63, path .../\{version\}/auth/payment). Panggilan ini menahan dana; Capture (65) nantinya menagih sebagian atau seluruh jumlah yang ditahan, Void (67) melepaskan dana yang ditahan namun belum di-capture.

Items didokumentasikan sebagai daftar barang yang dibeli tanpa skema level-item yang lengkap di mana pun selain goodsId/price/category/unit/quantity pada contoh kerja — dimodelkan sebagai json.RawMessage, mengikuti perlakuan package ini yang sudah baku untuk field yang benar-benar tidak bertipe (alasan yang sama dengan AdditionalInfo; juga sudah dipakai untuk AccountBindingRequest.AdditionalData, VerifyOTPResponse.QParams, dan CPMPaymentRequest.Items, yang terakhir ini persis nama field dan bentuk yang sama).

| Field | Type | Presence |
|---|---|---|
| `partnerReferenceNo` | `string` | Wajib |
| `merchantId` | `string` | Wajib |
| `subMerchantId` | `string` | Opsional |
| `amount` | `*snap.Money` | Opsional |
| `feeType` | `string` | Opsional |
| `mcc` | `string` | Opsional |
| `productCode` | `string` | Opsional |
| `title` | `string` | Wajib |
| `items` | `json.RawMessage` | Opsional |
| `additionalInfo` | `json.RawMessage` | Opsional |

**Response &mdash; `AuthPaymentResponse`**

AuthPaymentResponse adalah body response untuk API Auth Payment. ReferenceNo bersifat Kondisional (hanya saat sukses). Riset tidak menandai container Amount di sisi ini, sama seperti sisi request, tetapi menandai kedua anggota value/currency-nya Wajib; Amount dimodelkan sebagai snap.Money biasa (bukan pointer) — berbeda dari sisi request yang *snap.Money — karena ini adalah response sukses untuk sebuah hold yang baru saja dipasang, dan sebuah amount diharapkan selalu ada di dalamnya. Ini adalah keputusan yang lebih sempit dibanding kasus container-Opsional yang ditandai di tempat lain dalam package (bandingkan AuthPaymentQueryResponse.Amount, yang secara eksplisit ditandai riset sebagai amount O dan dimodelkan sebagai *snap.Money).

| Field | Type | Presence |
|---|---|---|
| `responseCode` | `string` | Wajib |
| `responseMessage` | `string` | Wajib |
| `referenceNo` | `string` | Opsional |
| `partnerReferenceNo` | `string` | Opsional |
| `amount` | `snap.Money` | Wajib |
| `paidTime` | `string` | Wajib |
| `additionalInfo` | `json.RawMessage` | Opsional |

### `AuthRefund`

AuthRefund memanggil endpoint SNAP Refund (Service Code 69, HTTP POST — tanpa override method, resolusi GET/POST yang sama seperti AuthPayment, Fase 31). hb harus sudah membawa setiap field yang dibutuhkan snap.HeaderBuilder kecuali Body, yang diisi sendiri oleh AuthRefund agar byte hasil marshal yang persis sama dipakai baik untuk signing maupun body di jalur kirim.

**Request &mdash; `AuthRefundRequest`**

AuthRefundRequest adalah body request untuk API Refund (Service Code 69, path .../\{version\}/auth/refund). Membalikkan jumlah yang sudah di-capture oleh Auth Capture (65).

OriginalCaptureNo bersifat Kondisional, "harus diisi saat transaksi tidak berhasil" — kebalikan dari arah kondisi kebanyakan field Kondisional di package ini, yang biasanya diisi saat sukses (riset §5.3). Dicatat di sini apa adanya, tidak disesuaikan; package ini tidak menerapkan validasi aturan-bisnis pada level field, sehingga arah pemicunya tidak berkonsekuensi pada kode selain catatan ini.

| `additionalInfo` | `json.RawMessage` | Opsional |

**Response &mdash; `AuthRefundResponse`**

AuthRefundResponse adalah body response untuk API Refund. RefundNo dan RefundTime bersifat Wajib. PartnerRefundNo bersifat Opsional di sini — berbeda dari response Direct Debit Payment Refund sendiri, tempat PartnerRefundNo bersifat Wajib (Fase 27) — dicatat per kemunculan, tidak diseragamkan.

OriginalCaptureNo dan OriginalReferenceNo sama-sama Kondisional, tetapi dengan pemicu sukses/gagal yang berlawanan satu sama lain: OriginalCaptureNo diisi saat transaksi tidak berhasil (kondisi yang sama dengan field request bernama sama), sedangkan OriginalReferenceNo diisi saat berhasil. Riset §6 butir 3 menandai ini sebagai belum diverifikasi secara independen — ini terbaca sebagai perbedaan yang genuine, bukan duplikat salin-tempel dari catatan yang sama, tetapi riset sendiri membiarkannya terbuka menunggu konfirmasi. Package ini memodelkan bentuk di wire sesuai yang didokumentasikan pada kedua arah (kedua field Kondisional → omitempty), karena tidak menerapkan validasi aturan-bisnis pada level field terlepas dari arah pemicu yang sebenarnya berjalan.
