## Direct Debit

Pembayaran direct-debit standar, notifikasi masuknya, dan status/batal/refund.

<CodeGroup>
```go example.go
resp, err := transferdebit.DirectDebitPayment(ctx, transport, hb, transferdebit.DirectDebitPaymentRequest{
	PartnerReferenceNo: "2020102900000000000001",
})
if err != nil {
	// errors.Is(err, snap.ErrBadRequest), snap.ErrUnauthorized, etc.
}
```
</CodeGroup>

### `DirectDebitPayment`

DirectDebitPayment memanggil endpoint SNAP Direct Debit Payment (Service Code 54, path .../\{version\}/debit/payment-host-to-host, HTTP POST — tanpa override method). hb harus sudah membawa setiap field yang dibutuhkan snap.HeaderBuilder kecuali Body, yang diisi sendiri oleh DirectDebitPayment agar byte hasil marshal yang persis sama dipakai baik untuk signing maupun body di jalur kirim.

Operasi ini tidak idempotent dan package ini tidak melakukan retry. Caller yang me-retry panggilan yang gagal atau timeout sebaiknya memakai ulang X-EXTERNAL-ID yang sama, karena deteksi duplikat di sisi server berpatokan pada header tersebut.

```go
func DirectDebitPayment(ctx context.Context, t *snap.Transport, hb snap.HeaderBuilder, req DirectDebitPaymentRequest) (DirectDebitPaymentResponse, error)
```

### `Direct Debit Payment Notification`

<Info>Hanya masuk (inbound) &mdash; package ini tidak memanggil endpoint untuk hal ini. Partner/switcher yang mengirim POST ke callback URL **Anda**; unmarshal body ke `DirectDebitPaymentNotificationRequest` setelah memverifikasinya dengan `snap.ServerVerifier` (lihat [Memverifikasi request masuk](/id/concepts/webhooks)), lalu balas dengan bentuk di bawah.</Info>

**Diterima &mdash; `DirectDebitPaymentNotificationRequest`**

DirectDebitPaymentNotificationRequest adalah body request untuk API Direct Debit Payment Notification (Service Code 56, path .../\{version\}/debit/notify). Ini adalah callback settlement yang diterima PJP, bukan panggilan yang dibuat package ini — tidak ada fungsi pemanggil yang disediakan, mengikuti konvensi baku package ini untuk endpoint notifikasi masuk (QRMPMPaymentNotificationRequest, Fase 23; NotifyBulkCashInRequest, Fase 18): caller memasang HTTP handler-nya sendiri untuk path ini, mengautentikasi panggilan masuk dengan ServerVerifier.VerifyTransactionRequest, dan melakukan json.Unmarshal pada body ke tipe ini.

OriginalReferenceNo dan LatestTransactionStatus bersifat Wajib menurut riset §5.1 baris 143; setiap field lain Opsional. Tidak ada apa pun pada baris tersebut yang menyatakan PJP mengirim panggilan ini keluar, sehingga pembacaan sebagai masuk (inbound) adalah default, bukan tebakan.

| Field | Type | Presence |
|---|---|---|
| `originalPartnerReferenceNo` | `string` | Opsional |
| `originalReferenceNo` | `string` | Wajib |
| `originalExternalId` | `string` | Opsional |
| `merchantId` | `string` | Opsional |
| `subMerchantId` | `string` | Opsional |
| `amount` | `*snap.Money` | Opsional |
| `latestTransactionStatus` | `string` | Wajib |
| `transactionStatusDesc` | `string` | Opsional |
| `createdTime` | `string` | Opsional |
| `finishedTime` | `string` | Opsional |
| `externalStoreId` | `string` | Opsional |
| `additionalInfo` | `json.RawMessage` | Opsional |

**Handler Anda membalas dengan &mdash; `DirectDebitPaymentNotificationResponse`**

DirectDebitPaymentNotificationResponse adalah body response yang dikirim balik caller untuk API Direct Debit Payment Notification. ApprovalCode adalah satu-satunya field di luar envelope, dan bersifat Opsional. Contoh kerja riset menunjukkan urutan field non-standar (responseCode, approvalCode, responseMessage) — dicatat di sini karena urutan field JSON tidak membawa makna semantik; struct ini tetap memakai urutan envelope-lebih-dulu yang baku pada package.

| Field | Type | Presence |

### `DirectDebitPaymentStatus`

DirectDebitPaymentStatus memanggil endpoint SNAP Direct Debit Payment Status (Service Code 55, path .../\{version\}/debit/status, HTTP POST — tanpa override method). hb harus sudah membawa setiap field yang dibutuhkan snap.HeaderBuilder kecuali Body, yang diisi sendiri oleh DirectDebitPaymentStatus agar byte hasil marshal yang persis sama dipakai baik untuk signing maupun body di jalur kirim.

Ini adalah query status yang hanya-baca dan tidak membawa catatan non-idempotency, mengikuti preseden TransactionStatusInquiryBank/TransactionStatusInquiryNonBank.
