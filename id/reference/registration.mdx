## Registrasi

Account binding, registrasi kartu, dan verifikasi OTP — package `registration` (Service Codes 01-10, 81). Ada dua alur di sini: alur **account** (binding berbasis OAuth, digerakkan oleh `GetOAuthURL` → `AccountBinding`) dan alur **card** (`CardRegistration` beserta varian Set Limit/Inquiry/Unbinding-nya).

<CodeGroup>
```go example.go
resp, err := registration.AccountBinding(ctx, transport, hb, registration.AccountBindingRequest{
	MerchantID: "...",
})
if err != nil {
	// errors.Is(err, snap.ErrBadRequest), snap.ErrUnauthorized, etc.
}
```
</CodeGroup>

**Request &mdash; `CardRegistrationRequest`**

CardRegistrationRequest adalah request body untuk API Card Registration (Service Code 01, path .../\{version\}/registration-card-bind). BankCardNo dan CustIDMerchant adalah dua field wajib menurut Guides tab — kolom Mandatory milik CardData sendiri kosong/tidak ditandai, bukan "M". CardData dan Limit bertipe json.RawMessage: Guides tab melabeli CardData "Encrypted Object" dan Limit "decimal", masing-masing mengizinkan representasi JSON bukan-string (objek murni, angka murni), meski satu contoh kerja portal me-render keduanya sebagai string berkutip. Pemanggil yang memasukkan string Go biasa harus mengutipnya dulu — mis. json.RawMessage(`"1000000"`), bukan json.RawMessage(limitStr), dan json.RawMessage(`"`+cardDataBase64+`"`), bukan json.RawMessage(cardDataBase64) — agar cocok dengan bentuk wire contoh kerjanya. Kesalahan ini TIDAK selalu tertangkap oleh json.Marshal: jika nilai tanpa kutip itu kebetulan sudah merupakan nilai JSON yang lengkap dan valid (mis. Limit diisi digit murni "1000000", tanpa nol di depan — angka JSON melarang nol di depan, jadi "01000000" akan gagal), ia ter-marshal dengan baik sebagai tipe JSON itu dan terkirim sebagai angka/objek/string murni — secara diam-diam menyimpang dari bentuk string-berkutip pada contoh kerja, tanpa error. Hanya nilai yang bukan nilai JSON valid dengan sendirinya (desimal berformat koma, blob base64 yang diawali huruf, string digit dengan nol di depan) yang menggagalkan json.Marshal dan mengembalikan error "encode request" sebelum request terkirim — ini jaring pengaman yang lebih sempit dan kurang andal dari kelihatannya, bukan jaminan. Dua bentuk lain: json.RawMessage kosong dihilangkan oleh omitempty (field absen dari wire body, tidak dikirim kosong), sedangkan json.RawMessage("null") TIDAK dihilangkan — ia dikirim sebagai "limit":null / "cardData":null eksplisit, karena omitempty hanya melewati slice berpanjang nol.

### `CardRegistrationInquiry`

CardRegistrationInquiry memanggil endpoint SNAP Card Registration Inquiry (Service Code 03, path .../\{version\}/registration-card-inquiry/custIdMerchant/\{value\} — parameter path URL, bukan field JSON body). hb harus sudah membawa setiap field yang dibutuhkan snap.HeaderBuilder kecuali Method dan Body, yang diisi sendiri oleh CardRegistrationInquiry: Method menjadi GET dan Body menjadi nil, karena ini satu-satunya endpoint read-only GET di package ini dan pemanggil seharusnya tidak perlu mengatur detail protokol khusus untuknya. hb.EndpointURL harus berupa URL http(s) dengan host, tanpa userinfo, dan tanpa query string atau fragment — CardRegistrationInquiry menolak URL yang tidak memenuhi itu, alih-alih diam-diam salah menanganinya (mis. fragment tidak pernah dikirim net/http sama sekali, jadi menambahkan sesuatu setelahnya akan diam-diam membuang custIDMerchant dari request sebenarnya tanpa error).

custIDMerchant divalidasi terhadap custIDMerchantPattern (lihat doc comment-nya), lalu digabungkan ke path hb.EndpointURL lewat url.URL.JoinPath — ini input pemanggil pertama di package ini yang mencapai path URL alih-alih JSON body, dan tempat pertama package ini mem-parsing URL alih-alih membangunnya lewat penggabungan string. JoinPath TIDAK "membiarkan RawPath apa adanya": ia membangun ulang path gabungan dari u.EscapedPath() lalu menurunkan ulang Path maupun RawPath dari string yang sudah di-escape itu (setPath milik net/url). Encoding yang sudah ada di EndpointURL tetap bertahan karena diteruskan lewat EscapedPath(), bukan karena RawPath dibiarkan utuh — RawPath justru selalu ditimpa. Perbedaan ini penting persis di sini: versi fungsi sebelumnya mengatur u.Path langsung (bentuk yang sudah di-decode) dan mengosongkan u.RawPath untuk memaksa penurunan ulang DARI PATH YANG SUDAH DI-DECODE, yang diam-diam mengubah "%2F"/"%2E%2E" yang sudah ter-encode di EndpointURL milik pemanggil menjadi batas path sungguhan sebelum request pernah terkirim. JoinPath menghindari ini karena ia mulai dari EscapedPath(), bukan Path.

func CardRegistrationInquiry(ctx context.Context, t *snap.Transport, hb snap.HeaderBuilder, custIDMerchant string) (CardRegistrationInquiryResponse, error)
