## QR / MPM

Merchant-Presented-Mode QR: generate, decode, bayar host-to-host, query, batal, dan refund — plus alur One-Time-Token yang dipakai ApplyOTT.

<CodeGroup>
```go example.go
resp, err := transfercredit.GenerateQRMPM(ctx, transport, hb, transfercredit.GenerateQRMPMRequest{
	PartnerReferenceNo: "2020102900000000000001",
	Amount: &snap.Money{Value: "500000.00", Currency: "IDR"},
	FeeAmount: &snap.Money{Value: "500000.00", Currency: "IDR"},
})
if err != nil {
	// errors.Is(err, snap.ErrBadRequest), snap.ErrUnauthorized, etc.
}
```
</CodeGroup>

### `GenerateQRMPM`

GenerateQRMPM memanggil endpoint SNAP Generate QR MPM (Service Code 47, path .../\{version\}/qr/qr-mpm-generate, HTTP POST — tanpa override method). hb harus sudah membawa setiap field yang dibutuhkan snap.HeaderBuilder kecuali Body, yang diisi sendiri oleh GenerateQRMPM sehingga byte hasil marshal yang persis sama dipakai baik untuk signing maupun wire body.

Operasi ini tidak idempotent dan package ini tidak melakukan retry. Caller yang melakukan retry atas call yang gagal atau timeout sebaiknya memakai ulang X-EXTERNAL-ID yang sama, karena deteksi duplikat di sisi server mengacu pada header tersebut.

```go
func GenerateQRMPM(ctx context.Context, t *snap.Transport, hb snap.HeaderBuilder, req GenerateQRMPMRequest) (GenerateQRMPMResponse, error)
```

**Request &mdash; `GenerateQRMPMRequest`**

GenerateQRMPMRequest adalah request body untuk API Generate QR MPM (Service Code 47). Setiap field bersifat Opsional menurut tab Guides — tidak ada field pada request ini yang terdokumentasi Wajib.

| Field | Type | Presence |
|---|---|---|
| `partnerReferenceNo` | `string` | Opsional |
| `amount` | `*snap.Money` | Opsional |
| `feeAmount` | `*snap.Money` | Opsional |
| `merchantId` | `string` | Opsional |

| `terminalId` | `string` | Opsional |
| `validityPeriod` | `string` | Opsional |

**Response &mdash; `GenerateQRMPMResponse`**

GenerateQRMPMResponse adalah response body untuk API Generate QR MPM.

QRContent, QRURL, dan QRImage membentuk kondisi salah-satu-dari-tiga yang tidak bisa dinyatakan sistem tipe: menurut tab Guides, "jika [qrContent] null, qrUrl atau qrImage harus diisi." Ketiganya di sini bersifat Opsional; caller harus mengecek mana di antara ketiganya yang terisi (tidak kosong).

### `QR MPM Payment Notification`

<Info>Hanya masuk (inbound) &mdash; package ini tidak memanggil endpoint untuk hal ini. Partner/switcher akan mengirim POST ke callback URL **milik Anda**; unmarshal body ke `QRMPMPaymentNotificationRequest` setelah memverifikasinya dengan `snap.ServerVerifier` (lihat [Memverifikasi request masuk](/id/concepts/webhooks)), lalu balas dengan bentuk di bawah.</Info>

**Diterima &mdash; `QRMPMPaymentNotificationRequest`**

QRMPMPaymentNotificationRequest adalah request body untuk API Payment Notification (Service Code 52, path .../\{version\}/qr/qr-mpm-notify). Ini adalah callback settlement yang diterima PJP, bukan call yang dilakukan package ini — tidak disediakan calling function, sesuai konvensi package ini untuk endpoint notifikasi masuk (NotifyBulkCashInRequest, Phase 18): caller memasang HTTP handler sendiri untuk path ini, mengautentikasi call masuk dengan ServerVerifier.VerifyTransactionRequest, lalu melakukan json.Unmarshal body ke tipe ini.

OriginalReferenceNo dan LatestTransactionStatus wajib menurut tab Guides; setiap field lain Opsional. Tidak ada di research §5.9 baris 202 yang menyatakan PJP mengirim call ini keluar (bandingkan dengan bahasa eksplisit "Callback yang dikirim PJP keluar" pada VA Notify Payment Intrabank, §5.3 baris 154 — satu-satunya pengecualian yang terkonfirmasi atas default ini), sehingga bacaan inbound adalah default, bukan tebakan.
