---
title: "Transport"
description: "Bagaimana signed request sebenarnya dikirim, dan bagaimana response di-decode"
---

`Transport` adalah lapisan HTTP tipis yang dipakai calling function di
setiap domain package untuk mengirim request yang dibangun `HeaderBuilder`
dan men-decode responsnya.

## `Transport`

```go
type Transport struct {
	HTTPClient *http.Client
}
```

```go
func (t *Transport) Do(ctx context.Context, hb HeaderBuilder) (Envelope, error)
```

`Do` menandatangani `hb` (lewat `hb.Build()`), mengirimnya, dan men-decode
response body menjadi `Envelope`. Ia **tidak** melakukan retry,
rate-limit, atau menafsirkan `responseCode` non-2xx sebagai error Go —
hanya kegagalan level transport (error pembuatan header, error jaringan,
body bukan JSON, pembatalan context) yang dikembalikan sebagai `error`.
Menafsirkan response yang sudah di-decode sebagai sukses/gagal adalah
tugas pemanggil, lewat `snap.CheckResponseStatus` (lihat
[Error](/id/concepts/errors)).

Saat `HTTPClient` dibiarkan nil, `Transport` membangun satu dengan timeout
default dan, yang penting, kebijakan `CheckRedirect` yang **tidak pernah
mengikuti redirect**: kebijakan default `net/http` menyalin setiap header
selain `Authorization` — termasuk `X-SIGNATURE`, `X-CLIENT-KEY`, dan
`X-PARTNER-ID` bertanda tangan milik package ini — dan, untuk 307/308,
seluruh body, ke host manapun yang disebut server. Tidak ada endpoint SNAP
yang punya alasan sah untuk redirect, jadi `Do` memperlakukan response
redirect seperti status non-2xx lainnya alih-alih mengikutinya.

Response body dibatasi ukurannya saat dibaca, sehingga server yang
bermasalah atau jahat tidak bisa memaksa penggunaan memori tak terbatas.

## `Envelope`

```go
type Envelope struct {
	StatusCode      int
	ResponseCode    string
	ResponseMessage string
	Raw             json.RawMessage
}
```

`Envelope` adalah response generik yang sudah di-decode: `StatusCode` HTTP
level transport ditambah field envelope SNAP apapun yang dibawa body.
Calling function di setiap domain package meng-unmarshal `Raw` ke response
typed miliknya sendiri.

`StatusCode` penting karena `ResponseCode` hanya bisa diandalkan ketika
server benar-benar mengembalikan bentuk error SNAP sendiri — body dari
proxy, WAF, atau gateway di depannya mungkin tidak membawa `ResponseCode`
sama sekali. Binding yang tidak punya `ResponseCode` untuk fallback
sebaiknya menggunakan `StatusCode`, pola yang sama yang dipakai
`TokenManager` secara internal.
